# Domain docs

Before exploring the codebase, read `CONTEXT-MAP.md` and then the `CONTEXT.md` for each context relevant to the work. Also read relevant decisions in root `docs/adr/` and any context-scoped `docs/adr/` directory.

If a context document or ADR does not exist, proceed silently. Create domain documentation only when a term or decision needs recording.

Use the vocabulary defined by the relevant context document. If a requested change conflicts with an existing ADR, state the conflict explicitly rather than silently overriding it.
